# 互动个性化落地方案

本轮从三门课程的课外训练接入互动诊断，不增加学科，不接入外部 STS 记忆工程。

1. 互动诊断：观察当前作答，提出待验证错因，最多追问三轮，返回当前题接受现有评测核验。
2. 过程交互：逐步补充 C 执行过程、操作系统状态推演、安全实验产物的交互展示。
3. 持续个性化：将跨次诊断和独立复测证据纳入学习记录与后续计划，验证先前假设。
4. 效果展示：证据时间线、明确标识的双学生演示、小规模学习效果验证。

## 本轮实现

训练中心的过程作答页增加“AI 互动诊断”。使用 OPENAI_MODEL 对应的现有模型客户端，根据题目、当前草稿、最近两次提交和本次对话生成追问。三门课程共用接口，提示词区分课程重点。

用户可回答、不确定、跳过追问或结束。记录存入原练习，可刷新恢复。课内作业和测验暂不开启该入口。服务端在调用模型前检查练习归属和任务限制，提交响应时复查作答版本，防止并发覆盖。

模型输出始终展示为待验证假设，不修改分数。诊断标记辅导使用；后续提交仍由原评测判定并进入学习状态和计划依据。当前题通过表示辅导后完成，不能替代新题独立复测。已有换题与延迟复测流程继续使用。

本轮没有新增跨次对话画像或自动验证错因结论；这属于第三阶段。也没有将当前题订正包装成迁移能力验证。

## 验证

专项覆盖三门课程、三轮上限、记录持久化、辅导标记、模型失败、跨用户隔离、作业限制、过期回复和退出跳过。真实配置模型分别检验 C 指针、LRU 和 DH 计算的首轮追问。测试使用隔离数据库和聊天记录。

验收结果：包含 Docker 的全量回归 286 项通过，前端构建通过；浏览器验证首次追问、不确定、跳过核验及刷新恢复。正式数据库及聊天记录与备份一致。

## 第二阶段：过程预测与回放

过程作答页接入“逐步预测与推演”。每一步先记录预测或判断依据，再由原有确定性求解器展开一个参考步骤；可前后回看已展开步骤，刷新后恢复。

- C：现有执行跟踪检查点；完整程序使用实际提交后的用例输入、期望输出、实际输出与编译反馈。
- 操作系统：页面置换前后页框、调度时间片、安全序列，以及已有检查点题型的逐步依据。
- 安全：计算、权限、日志等检查点；真实实验回放输入、产物名称、大小、权限和评测结果，产物下载沿用现有入口。

预测、展开结果与时间随练习保存，最近六条进入 AI 互动诊断上下文。自由文字预测不自动判分；展开过程记作辅导，已完成的独立提交证据不被追溯更改。新一次程序或实验提交后重新展开该次运行，避免混合不同运行的产物。

参考过程不表示唯一合法解。代码修复和 PV 方案设计继续使用已有核验；本轮未实现任意 C 程序的单步调试器、可任意修改参数的算法模拟器或完整浏览器实验终端。课内作业和测验关闭过程展开入口，并在后端强制检查。

第二阶段验收：完整回归 291 项通过；页面字段整理及新增跨提交回放用例后，6 项专项测试再次通过，前端构建通过。浏览器实测 C 指针、LRU、DH 的预测和逐步展开，验证前后回看与刷新恢复。真实模型能依据指针预测继续追问。正式数据库、聊天记录与发布前备份一致。

## 第三阶段：跨次学习记录与持续个性化

直接从现有练习、互动诊断、过程预测和提交记录重建个人记录，不引入外部 STS 系统，也不保存一份容易与成绩不一致的永久能力标签。

课程进度显示当前目标范围内最近 12 条互动记录，展示当时的待验证假设、回答、预测及最近 4 次后续核验。按同一知识点和时间先后关联；不同题目首次独立通过、辅导或订正通过、再次出错分别呈现。关联只表示知识点层面的后续证据，不声称证明具体心理错因。原互动和核验记录均可打开。

AI 学习计划接收跨次记录，互动记录变化会使旧计划失效，基础安排继续根据最新作答运行，重新生成 AI 计划沿用原按钮。新一次互动诊断读取本课程此前记录，避免每次从零开始。记录按用户隔离，当前目标范围过滤；课内任务记录和未公布测验相关知识点不进入该记忆摘要。

摘要随当前评测结果重新计算，因此评测复核修订不会留下与新成绩冲突的永久摘要。对话假设一直标注为待验证，辅导后通过不能升级为独立掌握。

第三阶段验收：包含 Docker 的完整回归 296 项通过，前端构建通过；浏览器验证跨次记录展示，并使用真实模型生成引用既往预测的计划。根据生成结果补强“辅导原题不能产生新题独立证据”的提示约束。正式数据库和聊天记录与发布前备份一致。

## 第四阶段：证据时间线与路演

课程进度增加个人证据时间线，展示当前目标范围内最近 80 条课外事件，包括开始练习、预测、互动、提交、辅导与评测复核。提交显示当时的历史结果，复核另列事件，当前判定仍以练习记录为准。按用户、课程、目标范围和未公布测验限制过滤。

同页提供双学生对照演示，可在三门课间切换，逐步展开或查看完整对照。两人从相同原题错误出发，均接受过程辅导并订正；新题中 A 首次独立通过，B 仍出错。评测、记忆摘要和学习安排使用实际服务计算。预测为预设脚本，不调用 LLM，界面始终标注模拟数据，临时库结束即删除。

模拟功能验证报告：`output/learning_evaluation/personalization_flow.json`。运行 `python scripts/evaluate_personalization_flow.py` 可复现。覆盖三门课、六条模拟路径、十二项一致性检查；真实参与者为零，不代表教学效果。

### 三分钟路演顺序

1. 在课程进度打开模拟演示，明确说明是可重复回放的模拟路径。
2. 逐步展示两人相同的首次错误、预测与订正，指出订正通过不等于独立掌握。
3. 展开新题结果：A 获得独立证据，B 仍需要订正。展示系统当前安排及依据。
4. 切换另外两门课，说明机制共用、训练内容不同。
5. 回到个人时间线，说明真实使用中能追溯原练习；展示真实模型读取先前预测生成的计划时，明确与预设演示的区别。

### 真实试用验证方案（尚未执行）

先开展一次探索性试用，建议招募 24 名自愿参与者，每门课 8 人；每人只参与一门课，根据前测水平分层后，随机分为基础训练与互动个性化训练两组。样本用于检查流程和估计方向，不能宣称证明普遍提升。

两组使用相同知识点、练习时间与题库难度；基础组沿用普通训练，实验组加入过程预测、互动诊断和个性化安排。推荐过程：10 分钟前测、25 分钟训练、10 分钟即时新题测验，7 天后完成延迟新题测验。前后测题须预先独立审校，参数与训练题不同，测验期间不开放提示和 AI。记录缺席与中途退出，不把缺失测验计作零分。

主要指标是未见新题的独立正确率及相对前测的变化；同时记录延迟正确率、任务完成时长、辅助次数、模型失败率和退出比例。按课程和组别报告样本数、原始分布与缺失情况，避免只展示成功个案。优先报告描述性结果与不确定性；若训练题和测验题泄漏或两组时间不一致，应注明，不能归因为个性化能力。

使用匿名参与者编号，征得试用与数据使用同意后记录课程、组别、前测、即时后测、延迟后测、练习编号与实际辅助情况。不得将模拟学生、演示事件或教师手工演示记录混入效果样本。目前没有真实参与者数据，因此没有生成提升幅度、显著性结论或有效性声明。

第四阶段验收：299 项完整回归通过，前端构建通过，12/12 项模拟功能检查通过。浏览器验证三门课演示切换、逐步展开、完整对照和个人时间线。正式数据库及聊天记录与发布前备份一致。真实试用尚未开展。

## LangGraph 编排迁移（2026-10-03）

本轮直接替换原 AI 工作流编排，保持原业务服务、接口和判题逻辑。

| 图 | 节点与分支 |
| --- | --- |
| deepsearch_plan | 拆题 → 学科路由 → 检索任务 → 检索 → 证据评审；不足时改写并回到检索任务 |
| deepsearch_answer | 执行检索子图 → 流式生成最终回答 |
| auto_qa | 路由 → 快答或深搜；快答评审后接受、补充学科检索或升级深搜；预算不足按原策略保留候选结果 |
| auto_supplement | 获取第二学科证据 → 合并与评审 |
| learning_dialogue | 权限与版本检查 → 历史证据 → 模型追问 → 输出校验 → 原子保存；跳过或退出直接进入关闭与保存 |
| learning_plan | 读取证据 → 生成计划 → 时间、任务和优先级校验 → 检查证据版本并保存 |

深度问答原先带阶段通知与不带通知的两套循环已合并。仍使用前端现有阶段事件，不把内部图状态直接输出给客户端。问答 HTTP 入口只有 `/api/chats/<chat_id>/messages/stream`。快速问答的旧 `answer_instant` 和 `ask_instant_mode` 包装已删除，内部需要候选结果时也复用流式调用；Auto 候选评审前仍缓冲，避免把未接受答案提前展示。

图运行使用请求内状态。跨轮诊断仍由现有 SQLite 记录与版本检查恢复，不增加第二套成绩或用户记忆库；本轮没有配置 LangGraph checkpointer，也没有实现服务崩溃后恢复到请求中间节点。模型超时、非法输出和证据过期沿用原有错误处理，不对写成绩、保存对话等操作增加自动重试。

回归重点包括检索改写、阶段事件顺序、流式片段、候选评审前不输出、Auto 各分支、超时预算、取消请求时后台任务清理、诊断版本冲突、用户隔离和计划校验。

迁移验收：304 项完整回归通过（包含 Docker 程序评测和安全实验），前端构建通过。隔离测试账号的真实 SSE 请求中，Auto 返回 23 个文本片段，DeepSearch 返回 110 个文本片段；三门课互动诊断与个性化计划的真实模型调用通过。诊断和深搜各出现过一次原有时限内未完成的请求，分别在独立复验后成功；这只验证功能链路，不代表上游延迟已经稳定。未修改超时上限。新版本地服务已启动，正式数据库行内容和聊天记录与发布前备份一致。

### Instant 改为模型直答

Instant 使用 `OPENAI_MODEL`，仅带当前问题与会话上下文流式回答。即使手动指定课程，也不运行检索网关、知识库路由、向量检索或局部图谱查询，不自动转入代码分析和题目辅导链路。前端流程图同步改为“用户问题 → LLM 直答”，只展示一个直答节点与总耗时，移除 Instant 的检索参数展示及废弃配置项。

Auto 的首轮候选同步改为模型直答，评审提示明确候选未经检索；长答案也不能跳过评审，评审失败或无法确认时继续补充检索或升级深搜。第二学科证据仍通过单独的检索方法获得，不再借用 Instant。DeepSearch 的 `top_k`、`chunk_top_k` 和改写重检策略保持原样。SSE 文本片段数量是回答传输粒度，与检索 topK 和模型调用次数无对应关系。

本轮验收：304 项完整回归通过，首段立即输出的调整后，37 项相关测试再次通过，前端构建通过。真实 Instant SSE 请求无需检索即可完成；额外计时样本总耗时 11.30 秒，其中模型流式接口占 11.29 秒，首个文字在 3.31 秒到达。移除首段攒字等待，后续片段仍适度合并。单次样本不能代表长期延迟。

流程图同步修正：单学科的质量评审未通过或超时后可以直接升级 DeepSearch，补第二学科及合并评审均可跳过。节点状态优先采用真实执行事件，最终输出不再因执行 DeepSearch 而误标“跳过”；跳过节点不显示耗时，评审失败显示“评审未完成”。用实际请求记录验证了分支、最终输出、错误状态和 Instant 单节点展示，浏览器中复核了连线。

## DeepSearch / Auto 断点恢复（2026-10-03）

在上述编排迁移基础上接入持久化 checkpoint。使用官方 `langgraph-checkpoint-sqlite` 的异步 saver，每个请求中的命名图单独保存进度，采用同步落盘模式。完成的节点不重跑，父节点重试时也能继续尚未完成的子图；进程退出后，重新创建服务仍可读取进度。当前默认文件为 `data/learning_workflows.sqlite3`，自定义学习库路径时使用同目录的 `<学习库名称>_workflows.sqlite3`。

前端在失败或中断的最新请求下显示“继续上次回答”。恢复仍通过 `/api/chats/<chat_id>/messages/stream`，提交 `resume_run_id` 与非空 `message`；服务端按已保存的原始请求和会话上下文执行，不接受客户端替换模式、学科或问题。恢复前重新校验登录、聊天归属及关联练习的访问权限。进程锁防止同一聊天同时执行两个恢复请求，进程退出会自动释放锁。已有更新的提问后，旧请求不能继续恢复。

恢复时重新展示这一条回答，替换先前的半截内容。失败记录不写入会话摘要；成功结果按任务编号替换原问答，重复恢复完成任务只回放结果，不重复调用模型或追加问答。删除聊天时一并删除请求记录和 LangGraph 检查点。运行中的回答可在重新打开页面后继续等待，页面自动刷新其完成状态。

边界：恢复点位于已保存的工作流步骤之间；尚未完成的模型调用会重跑，不能从某个 token 接着生成。每次恢复获得一次新的执行时间预算。Instant、互动诊断、学习计划及普通业务服务未在此阶段接入 checkpoint，原有学习证据和成绩数据库继续使用。当前按单机服务验证；多实例部署仍须处理聊天存储并发和分布式锁；工作流结构发生不兼容修改时须更新请求版本号，拒绝恢复旧版本。

验收：311 项完整回归通过，包含 Docker 程序与实验测试；前端构建通过。新增测试覆盖嵌套图恢复、真实子进程退出后恢复、Auto 已完成结果复用、账号隔离、并发锁、旧任务失效、恢复后问答去重及删除检查点。浏览器使用受控中断验证恢复按钮、半截回答替换与重复问答检查。真实 DeepSearch 请求完成后，重启服务并连续恢复两次，回答记录保持两条且内容不变。补充真实 HTTP 连接复用测试，并移除与服务器连接管理冲突的显式 keep-alive 响应头。

## Auto 回答速度优化（2026-10-03，第一项）

本轮只处理回答速度与可核对的计时。明确要求课程资料、出处或推导论证时，Auto 直接进入 DeepSearch；手动选中单门课不再覆盖这些请求，也不覆盖已有的高置信复杂度判断。只看当前问题的明确请求，不让历史对话中的引用要求强迫后续简单追问深搜。否定引用请求与非课程问题保留原路由边界，其余问题继续走快答和质量评审。

删除额外的 5 秒快答评审上限，统一使用 `AUTO_REVIEW_TIMEOUT_S` 和剩余请求预算。原四个真实样本均在这层短上限处超时，继而转入深搜。空回答、明确失败的候选直接进入补充检索或深搜，不再额外调用模型评审；长答案仍须评审，不能靠字数判定正确。

删除服务端已生成答案的定时分片等待，Auto 深搜最终生成直接传递流式文本。删除前端按字符延迟播放、等待播放结束以及以播放时间覆盖服务端节点耗时的实现，改成按浏览器渲染帧合并已经收到的文本；结束和异常时立即刷新剩余内容。要求简短回答时保留核心结论、必要条件、证据及不确定性，不再强制展开六至八节固定模板；没有长度要求时保持原教学结构。

回答详情新增 `responseTiming`：`firstTextMs` 是服务端开始处理至首段最终文字输出的时间，`totalMs` 截至答案生成完成，`outputMs` 是首段之后的输出时间，`reviewMs` 仅累计本次实际执行的 Auto 评审步骤。没有首段或没有执行评审时对应值为 null；旧记录缺少该字段时不显示新计时。会话存储和网络传输不包含在服务端指标中，客户端基准脚本另外测量端到端耗时。恢复任务复用旧节点时，不把历史评审耗时计入本次请求；已完成任务回放保留原回答计时。

`scripts/benchmark_auto_latency.py` 对三门课资料问题和一个简单 C 概念问题逐条创建独立聊天，记录首段、总耗时、最终答案及执行路径。运行时指定隔离服务地址、测试用户名、输出路径，并将测试密码写入 `TEACHING_BENCHMARK_PASSWORD`；可用 `--repeats` 增加采样次数。此脚本只验证本项的性能与路径，不替代后续完整质量评测集。

验收：320 项完整回归通过（含 Docker），最终计时调整后 46 项相关测试再次通过，前端构建通过。浏览器验证 3004 字受控回答可在 1.5 秒内完整显示，服务端节点耗时未被覆盖。三门课资料题均跳过快答和快答评审；sizeof(char) 简单题通过模型评审，保持快答。

## 2026-10-03 第二项：流式重连与停止生成

每次问答执行写入带递增序号的事件记录，覆盖 Instant、Auto、DeepSearch、代码分析和题目辅导。浏览器连接与后台任务分离，断开连接不会重新调用模型；刷新时补收本次执行的全部事件，短暂断线则从最后接收的序号续收。前端最多自动重连三次，仍不通时提供“重新连接”和“停止生成”。切换会话会释放当前接收连接，返回时接回任务，迟到事件不能写进另一段会话。

停止请求同时校验用户、会话、任务及执行编号，取消实际异步任务，关闭上游流、清理图谱/Auto 并行任务及正在运行的代码分析子进程。清理完成后才释放会话锁。保留已输出文字，回答标记为“已停止生成”，不把不完整回答写入会话记忆摘要。已经完成的回答不会被迟到的停止请求改成取消；旧执行的停止和重连请求不能作用于后续重试。远端模型服务是否继续计费仍取决于供应商，不以本地取消状态作保证。

Auto、DeepSearch 普通问答继续使用已有 LangGraph checkpoint 恢复；Instant 和专用分析流程保留原请求参数供“重新生成”，不冒充节点级恢复。每次恢复创建新的执行编号，仍以原任务编号恢复 checkpoint，并替换原中断回答。历史运行记录自动补齐新字段；删除聊天时一并删除事件和 checkpoint。事件的定期保留策略留待第六项统一完成。

新增接口：`GET /api/chats/<chat_id>/runs/<run_id>/events?execution_id=...&after=...`；`POST /api/chats/<chat_id>/runs/<run_id>/cancel`，请求体包含 `execution_id`。事件接收期间持续检查登录及聊天权限。

验收：326 项完整回归通过（含 Docker），补充上游流关闭后的相关测试及 7 项生命周期测试通过，前端类型检查和构建通过。真实 HTTP 测试覆盖断线续收、停止前后状态、跨用户权限、旧执行隔离、DeepSearch 复用检索、旧数据库迁移和聊天事件清理。无界面浏览器验证刷新连续接收、受控断线后从事件 8 续收、切换会话后接回原任务且不串入文字、停止后保留文字；模型替身每次仅执行一次，取消后确实退出。正式学习数据库及聊天记录保持不变。

## 2026-10-03 第三项：问答质量与引用核验

DeepSearch 与 Auto 补充检索直接传递原始片段，删除检索后先生成摘要再作为证据的路径。每条证据必须与课程索引中的片段、所属原文相符；剔除缺失、错配和只有元信息的片段。图检索没有有效原文时才补做向量检索，沿用当前 topK。最终生成统一使用 E1、E2 等编号，页面展示实际参与回答的原文、标题和文件，不再把另一次图谱查询命中的片段作为回答出处。

发现并修复三门课共用空 LightRAG workspace 的问题：各课程使用独立 workspace，实际索引目录保持原路径，不要求重建。测试在三门课存储中写入相同编号的不同内容，确认不再串用数据。

按用户确认的范围，删除回答后的 LLM 引用复核节点、界面复核状态和模型评分工具，也撤回未完成的模型筛选原文尝试。原有 Auto 快答选择与 DeepSearch 检索编排保留，不追加多轮自审。未知引用编号仍显示“出处未核实”；原文可核对不意味着每个解释都绝对正确。

异步检查点与同步流式事件分别保存，避免并发写锁互等；删除会话同时清理对应记录。移除复核节点后工作流版本为 3，旧版中断任务按原参数重新生成，旧完整回答仍可查看。

`scripts/check_qa_sources.py` 和 `tests/fixtures/qa_source_cases.json` 仅验证真实 SSE 完成、引用编号及原文文件匹配，不调用额外模型评分。此前质量抽检报告仍保留在 `output/qa_quality/` 作为历史排查记录，6/12 不再作为发布或进入下一阶段的门槛。

本项删减后的 46 项问答、引用与恢复专项测试通过；不再使用模型语义评分作为验收条件。

## 2026-10-03 第四项：个性化推荐效果核验

复用现有推荐与作答记录，在“课程进度”的学习计划中展示“推荐效果核验”，知识点详情同步展示。统计同知识点推荐前后首次独立作答的通过数和总数，首次答错也进入分母；提示、看答案、重复题和订正记录另列，不作为新题独立通过。没有后测时显示待验证，不生成提升率。尚未完成推荐练习时，其他练习的通过不会被归给该推荐；阅读与讲解只观察完成后的作答。

即时通过后继续等待间隔核验。新题必须在推荐任务完成至少一天后才开始，且首次独立通过；提前打开、隔天提交不算间隔核验。后续仍有错误时回到需要巩固。同知识点期间接受的其他推荐一并披露，不把观察到的变化解释成单项推荐的因果效果，也不以一次间隔通过替代原有完整复习安排。

核验结果由当前有效判定实时计算，成绩复核后同步重算。未公布测验继续隐藏相关知识点核验，学生之间隔离。AI 计划和针对性讲解读取同一份核验结果；新证据使旧 AI 计划失效，避免沿用过期安排。没有新增模型调用或第二套推荐存储。

验收：349 项完整回归通过，包含 Docker 程序与安全实验；前端类型检查及构建通过。新增检查覆盖三门课统计一致性、失败分母、辅助与重复排除、间隔边界、推荐重叠、判定复核、账号与测验权限，以及 AI 上下文和缓存失效。原有三门课模拟流程 12/12 通过，这些都是功能检查，不是实际教学效果研究。无界面浏览器确认独立作答前后数量、订正与间隔新题分类及练习入口。正式学习、学校数据库及聊天记录未修改。

## 2026-10-03 第五项：互动诊断与 AI 学习计划断点恢复

两条学习工作流复用现有请求记录、进程锁和独立 SQLite checkpoint 文件。每轮诊断与每次计划生成分别保存执行进度，原有跨轮诊断、作答和成绩仍保存在学习库。完成的证据采集与有效模型输出不重复执行；尚未完成的模型调用重新调用，不承诺 token 级续写。格式校验放在生成节点内，防止无效模型输出被保存为永久无法继续的恢复点。

原 POST 接口接受可选 `resume_run_id`；同路径新增 GET 查询本人的执行状态。恢复只读取服务端保存的原请求，忽略客户端尝试替换的回答、操作和版本。每次恢复重新校验账号、练习与班级访问权限；当前练习的作答或诊断版本已变，或者计划证据、目标、候选任务已变时，拒绝旧任务并要求重新开始。新任务使旧任务失效，同一用户同一目标的并发请求由现有文件锁阻止。课内任务及访客演示继续禁止 AI 诊断。

保存诊断和计划时记录本次工作流编号。业务记录已经提交而 checkpoint 或 HTTP 返回尚未完成时，恢复直接读取当前业务结果，不重复增加诊断轮数、写入事件或覆盖计划。互不相关的练习与课程可以分别执行，不新增成绩库或第二套模型调用实现。

前端显示“继续上次诊断”和“继续上次计划”。页面刷新、切换后重新查询状态，后台请求完成后自动刷新业务结果；当前仍在执行时禁用重复生成。新一轮诊断完成后清空回答框，恢复失败轮次时使用已保存的原回答。刷新诊断状态不覆盖学生未保存的作答输入。

验收：357 项完整回归通过，含 Docker 程序及安全实验；前端类型检查和构建通过。恢复专项覆盖超时、无效格式、过期证据、原请求防篡改、账号和班级权限、并发锁、旧任务失效、保存后异常及真实子进程退出后复用已完成模型节点。无界面浏览器分别验证计划与诊断首次受控失败后继续，执行中刷新仍能收到完成结果；两条路径各记录一次失败调用和一次继续调用，刷新未增加调用。正式学习、学校数据库和聊天记录保持不变。checkpoint 与历史事件保留策略仍留待下一项统一处理。

## 2026-10-03 第六项：工作流恢复数据保留与清理

应用正常启动时启动一个后台清理线程，立即检查一次，之后每小时检查，每轮最多处理 100 条候选记录。已完成或被新任务替代的执行，默认在最后更新时间满 7 天后清理；失败、取消，以及进程退出后遗留的中断执行，默认保留 30 天供恢复。`.env` 的 `WEB_WORKFLOW_COMPLETED_DAYS` 和 `WEB_WORKFLOW_RECOVERABLE_DAYS` 可调整这两个期限，必须为有限正数，重启后生效。

清理与生成、恢复共用同一资源文件锁。无论记录年龄和状态如何，仍持有执行锁的任务都跳过；取得锁后再次读取状态与更新时间，避免误删刚恢复的任务。跨数据库清理先将请求标记为过期，再删除新旧 checkpoint 库中的全部子图线程，最后删除流式事件和请求元数据。清理中途失败的请求不可恢复，下轮继续删除，避免缺少部分 checkpoint 后重新执行已完成步骤。旧版同库 checkpoint 和新版独立 checkpoint 都沿用同一删除实现，没有保留两套等价逻辑。

不清理聊天消息、引用原文、练习作答、成绩、互动诊断记录和已保存的 AI 学习计划。过期后仅失去该次执行的续传和节点恢复能力，仍可重新发起操作。已经释放的 SQLite 页面留给后续写入复用，不在在线服务中强制 VACUUM；数据库文件不一定立即变小。小型资源锁文件保留，避免删除锁文件引发并发执行使用不同锁的风险。

手动检查使用 `scripts/cleanup_workflows.py`，默认只预览，`--apply` 才执行；`--database` 可指定隔离工作流库，`--limit` 为每批 1 至 1000 条。脚本读取项目 `.env`，采用与服务相同的保留期限。在项目目录运行：

```bash
/opt/anaconda3/envs/teach/bin/python scripts/cleanup_workflows.py
/opt/anaconda3/envs/teach/bin/python scripts/cleanup_workflows.py --apply
```

回归同时修正了聊天快照的一个并发读取问题：查询工作流终态后再读取消息，避免停止生成时偶尔返回“已停止”但消息列表仍为空的旧快照。新增受控并发测试固定这一读取边界。

验收：366 项完整回归通过，包含 Docker 程序和安全实验；前端类型检查通过。专项覆盖保留期限边界、预览不删除、活动执行保护、获取锁后重新核对、跨库清理失败后续清、子图与旧版 checkpoint 清理、批量限制、后台线程生命周期，以及聊天终态和消息快照的一致性。正式库预览与实际清理均为 0 条到期记录，业务数据库与聊天内容核对未变。本地服务已启用启动检查和每小时清理。
